# 基金限购额度每日盯盘

从**天天基金网**抓取 **50 只**指数 / QDII 基金的**单日限购额度、申购状态、净值、规模**，
每天落一条记录到 SQLite，用网页随时查看与导出。

基金按四类管理，网页上有按钮随时切换：**标普（14）· 纳指100（31）· 纳指科技（2）· 主动（3）**，默认全部显示。

## 二、页面功能

| 区域 | 说明 |
|---|---|
| 额度总览 | 50 只基金最新一条记录：申购状态、单日限购额度、额度变化、净值、日涨幅、规模 |
| 分类切换 | 总览表右上的按钮：**全部 / 标普 / 纳指100 / 纳指科技 / 主动**，按钮上带只数；默认「全部」 |
| 额度变动提醒 | 最新记录 vs 上一次记录，额度或申购状态发生变化的基金自动高亮 |
| 历史记录 | 按基金 + 时间范围筛选每日记录，可导出 CSV（带 BOM，Excel 直接打开不乱码）|
| 额度走势图 | 静态阶梯图，数值直接标注在图上（对数刻度，10 元 ~ 1 万元可同图比较）；红点＝当日「暂停申购」|

页面右上角 **「立即抓取」** 按钮可随时手动补一条记录（50 只跑完约 1~2 分钟）。

### 分类切换

- 切分类**只影响显示，不重新请求接口**，点击即时生效；
- 右上提示会显示「记录日期 X ｜ 显示 N / 50 只」；
- 历史记录的下拉框也按分类分组（`标普（14）` 这样的分组标题）；
- 分类不是写死在代码里的，改 `funds.txt` 就能增删或改名，按钮自动跟着变。

表头「分类」列有配色区分：标普＝蓝、纳指100＝绿、纳指科技＝紫、主动＝橙。

### 表头排序（额度总览）

**默认按「单日限购额度」从多到少**。带 `⇅` 的表头可点击切换升序 / 降序（当前列显示 `↓` / `↑`）：

| 表头 | 降序（默认）| 升序 |
|---|---|---|
| 单日限购额度 | 从多到少 | 从少到多 |
| 额度变化 | 变大在前 | 变小在前 |
| 日涨幅 | 涨幅高在前 | 涨幅低在前 |
| 规模(亿) | 规模大在前 | 规模小在前 |

规则细节：
- **暂停申购按 0 元计**（与配色口径一致），所以「从多到少」时它们沉底，「从少到多」时排最前；
- 日涨幅 / 规模为空值的行**无论升序降序都排在最后**，不会窜到前面；
- 数值相同时按基金代码排，避免每次刷新顺序乱跳；
- 排序只影响页面显示，不改动数据库；重新抓取后仍保持当前排序。

### 展示规则（配色约定）

| 情况 | 显示 | 颜色 |
|---|---|---|
| 暂停申购 | 状态只显示「暂停申购」四个字；额度列显示 `—`（暂停申购没有限额一说）| 状态标签 **红色** |
| 限大额 / 开放申购（能买） | 额度正常显示，如 `100元` / `1万元` | 状态标签 **绿色** |
| 额度变化 —— 变大 | 如 `10元 → 100元` | **蓝色** |
| 额度变化 —— 变小 | 如 `1万元 → 100元`，变成暂停申购也算变小 | **黄色** |
| 仅状态变化（额度未变） | 如 `限大额 → 暂停申购` | 灰色 |

规则集中在 `fetcher.py` 的 `status_label()` / `is_buyable()` / `effective_limit()` 三个函数，
网页（`app.py` + `app.js`）与静态日报（`make_report.py`）共用同一套判定，改一处两边同时生效。

走势图中：<span>绿色点＝当日可申购</span>，红色点（标注「暂停」）＝当日暂停申购、无额度，画在坐标轴底端。

## 三、每日自动记录（GitHub Actions）

**不依赖你的电脑**：定时跑的是一台 GitHub 服务器，电脑关机、休眠、拔网线都不影响。
抓到的数据自动提交回仓库，日报同时发布到 GitHub Pages，手机上随时能看。

### 第一次部署（三步）

1. **建仓库**：GitHub 网页右上角 `+` → New repository → 填名字（如 `jijin`）→
   建的时候**不要**勾 Add a README / .gitignore / license（要的是空仓库）；
2. **上传**：双击项目根目录的 `上传到GitHub.bat`，把仓库地址粘进去回车，按提示登录一次即可；
3. **开 Pages**：仓库 Settings → Pages → Source 选 `Deploy from a branch`、分支 `main`、目录 `/docs`，Save。

之后就不用管了。想确认能不能跑通，去 Actions 页面点一次 Run workflow。

### 运行流程

```
GitHub 定时触发
   ↓
检出仓库 → 装 Python → 抓 50 只基金（run_fetch.py）
   ↓
生成日报 + 归档目录（make_report.py）→ 复制到 docs/
   ↓
把 data/ + report/ + docs/ 提交回仓库 → GitHub Pages 自动更新
```

### 时间点

GitHub 的 cron **一律按 UTC 算**，北京时间 = UTC + 8：

| 北京时间 | UTC cron | 抓什么 |
|---|---|---|
| 09:35 | `35 1 * * *` | 当天的限购额度与申购状态 |
| 21:30 | `30 13 * * *` | 当天的单位净值 |

改时间就编辑 `.github/workflows/daily.yml` 里的 `cron`（记得减 8 小时）。

### 想立刻跑一次

仓库 → **Actions** 标签页 → 左侧「基金限购额度 · 每日抓取」→ 右侧 **Run workflow**。
跑完在运行页面有一份 Markdown 摘要：成功几只、额度变动、额度分布、全部明细，不用下载文件也能看结果。

### 注意事项

| 事项 | 说明 |
|---|---|
| **首次要手动开 Pages** | 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/docs`，保存 |
| **60 天不活动会被停用** | GitHub 规则：仓库连续 60 天没有任何推送会暂停定时任务。本项目每次跑都会提交数据，正常不会触发；万一被停用 GitHub 会发邮件，去 Actions 页面点一下 Enable 即可 |
| **不保证精确到分钟** | 高峰期可能推迟几分钟到几十分钟，偶尔会跳过某一次；同一天的重复抓取不会产生重复记录 |

## 五、目录结构与便携性

运行环境（Python 解释器 + 三方库）**已经放在 jijin 文件夹内部**，不依赖 C 盘的 Python：

```
jijin/                          <- 整个文件夹可以直接拷到别的电脑
├── .github/workflows/daily.yml GitHub Actions 定时任务（每天 09:35 / 21:30 抓取）
├── .gitignore / .gitattributes 仓库忽略与换行规则
├── docs/                       GitHub Pages 目录（由 Actions 生成、提交）
├── 一键启动.bat                启动网页 + 自动开浏览器
├── 一键抓取.bat                抓一次 + 生成日报
├── 环境自检.bat                环境体检
├── setup_runtime.py            装配脚本（runtime 损坏时重跑它即可重建）
├── runtime/                    便携运行环境（Python 3.13.12 + flask + requests）
│   └── python/python.exe       ↑ 已加入 .gitignore，不进仓库（38MB）
└── fund_tracker/               业务代码与数据
    ├── app.py                  Flask 应用（页面 + API）
    ├── fetcher.py              天天基金抓取与解析
    ├── db.py                   SQLite 存储层
    ├── run_fetch.py            单次抓取（供 Actions / 批处理调用）
    ├── make_report.py          生成静态日报 report/YYYY-MM-DD.html + index.html
    ├── ci_summary.py           把抓取结果整理成 Markdown 摘要（Actions 运行摘要用）
    ├── funds.txt               基金清单（代码,分类 —— 改这里增删基金与分类）
    ├── config.json             端口、并发数、内置定时器开关
    ├── templates/index.html
    ├── static/style.css / app.js
    ├── data/funds.db           每日记录数据库（会提交回仓库）
    └── report/                 静态日报归档（会提交回仓库）
```

> `runtime/` 体积 38MB，**不提交到仓库**——它只是本地跑网页用的。
> GitHub Actions 那边由 `actions/setup-python` 现场装标准版 Python，不需要这个目录。

### 换电脑怎么操作

1. 把 **整个 `jijin` 文件夹**复制到新电脑（U 盘 / 网盘 / 移动硬盘都行）；
2. 双击 `一键启动.bat` —— 完成。

**不用装 Python、不用装依赖。** 因为：

- `runtime\` 用的是 Python **embeddable（嵌入式）发行版**，本身不含任何绝对路径，随文件夹移动不会失效；
- 所有脚本内部的文件读写都显式指定了 `utf-8`，与系统区域设置无关；
- `runtime\python\Lib\site-packages\sitecustomize.py` 按自身位置反推项目根目录并注入 `sys.path`，
  所以 `fund_tracker` 里的 `import db` / `import fetcher` 在没有项目目录的情况下也能找到——
  这也是嵌入式 Python 与普通 Python 唯一的差别（它会锁定 `sys.path`，必须显式补）。

**注意**：拷贝时不要把 `runtime\python\` 单独拆出去用，也别删 `sitecustomize.py`。
如果 `runtime\` 不慎损坏或丢失，双击 `一键启动.bat` 会自动重建；也可以手动执行：

```bat
cd /d D:\GREEN\项目\jijin
setup_runtime.py            :: 需要本机有 Python 3.9+ 且联网
```

## 六、增删基金

编辑 `funds.txt`，每行格式 **`代码,分类`**，`#` 后面可写备注（可选）。**`funds.txt` 是分类的唯一权威来源**，
改完刷新页面即生效（不用重新抓取，历史记录里的分类也会一起跟着改）：

```
# ============ 纳指科技（3 只） ============
017091,纳指科技      # 景顺长城纳斯达克科技ETF联接(QDII)A人民币
019118,纳指科技      # 景顺长城纳斯达克科技ETF联接(QDII)E人民币
017093,纳指科技      # 景顺长城纳斯达克科技ETF联接(QDII)C人民币
```

> 分类是「每只基金」的属性，不是「每条记录」的属性，所以改 `funds.txt` 后：
> 网页、历史记录、CSV 导出、静态日报会**立刻**用新分类；
> 数据库里已存的记录会在程序启动时自动回写纠正（`db.sync_categories()`）。
> 只有在基金被**从清单里删掉**时，才回落到库里原先存的值。

| 写法 | 结果 |
|---|---|
| `006075` | 只有代码，归入「其他」分类 |
| `006075,标普` | 代码 + 分类（推荐）|
| `006075,标普  # 备注` | `#` 后面被忽略，可随便写基金名称 |

规则：
- 分类名就是网页按钮上的名字，可自由增删改；**分类的先后顺序**在 `fetcher.py` 顶部的
  `CATEGORY_ORDER = ["标普", "纳指100", "纳指科技", "主动"]` 里调整，不在列表里的分类排在后面；
- 重复代码只保留第一次出现的；非 5~6 位数字的行会被忽略；
- 50 只基金全量抓取约 1~2 分钟，并发数在 `config.json` 的 `workers`（默认 8）。

## 七、常见问题

**Q：额度抓不到 / 显示「—」？**
A：部分基金开放申购且不限额，页面本身没有「单日累计购买上限」字样，此时额度栏显示 `—` 属正常。

**Q：某只基金抓取失败？**
A：`fetch_log` 里记了成功/失败数，失败的不会写库，下次抓取会自动补上。天天基金偶发限流，重试机制已内置。

**Q：为什么走势图只有 1 个点？**
A：限额是「当天快照」型数据，历史值无法回溯获取，只能从开始记录之日起逐日积累。

**Q：网页关掉 / 浏览器休眠了，内置定时还会抓吗？**
A：**会**。内置定时器是 `app.py` 里的一个后台线程（`scheduler_loop`），跑在
**Python 进程里**，跟浏览器完全没有关系——关标签页、关浏览器、锁屏都不影响。
唯一前提是那个「基金限购额度盯盘」黑窗口还开着（关掉窗口 = 停止服务，定时也就停了）。

但要注意**电脑睡眠 / 休眠**：睡眠期间进程被挂起，到点检查不到，
醒来后**不会补跑**当天已错过的那个时间点。若那台机器经常睡眠，建议：
- 主力靠 WorkBuddy 定时任务（有补跑窗口，程序关了也能跑）；
- 或者把 `config.json` 的 `fetch_times` 设成你确定机器醒着的时间点。

**Q：换电脑后双击没反应？**
A：确认 **整个 `jijin` 文件夹**（含 `runtime` 子目录）都复制过去了。若 `runtime` 缺失，
批处理会提示本机没有 Python——此时要么把 `runtime` 一起拷过来，要么先装 Python 3.9+ 再运行。

**Q：`一键启动.bat` 双击后窗口一闪而过？**
A：先跑一次 `环境自检.bat`，它会列出缺什么。窗口一闪通常是 `chcp` 或路径异常，自检能看到原因。

**Q：C 盘那个旧的 Python 环境还要吗？**
A：不需要了。本项目已自带便携环境，旧的
`C:\Users\hvvzhang\.workbuddy\binaries\python\envs\default\` 可以删掉释放空间。
